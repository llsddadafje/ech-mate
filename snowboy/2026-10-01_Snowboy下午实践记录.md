## 3. 唤醒词模型的基本概念

本次学习的是关键词检测／唤醒词检测（KWS），其核心任务是判断音频中是否出现指定词句。

- `.pmdl`：Snowboy 个人模型，通常由同一个人的几段唤醒词录音生成。
- `.umdl`：Snowboy 通用模型，面向不同说话者；一个模型可能包含多个唤醒词。
- 模型文件决定实际识别内容，改文件名不会改变唤醒词。
- 个人模型注册使用已有 Snowboy 引擎，不等于从零训练整个神经网络。

录音时要说出希望完整识别的内容。例如要用“你好小麦”唤醒，就在三个注册文件中分别完整说一次“你好小麦”；要用“小麦”唤醒，就分别只说“小麦”。不要附带“帮我开灯”等后续指令。

“你好小麦”只是本次讨论中的示例；实际模型的唤醒词以录音内容为准，对话中未明确给出最终使用的词句。

### 音频输入和检测返回值

本例要求 16 kHz、单声道、16 位有符号小端裸 PCM。每次读取 40 ms，相当于 640 个样本、1,280 字节。

`int16_t` 数组接口的长度参数是样本数，而不是字节数。连续检测要复用同一个检测器，让它保留跨帧状态。

| 返回值 | 含义 |
| --- | --- |
| 大于 0 | 检测到唤醒词，数值表示从 1 开始的唤醒词编号 |
| 0 | 无事件 |
| -2 | 静音 |
| -1 | 检测错误 |

学习示例读取裸 PCM，不直接解析 WAV 文件头。

## 7. 处理 Docker Hub 下载超时

首次构建在下载基础镜像时失败：

```text
failed to resolve reference "docker.io/library/ubuntu:16.04"
dial tcp 31.13.82.169:443: i/o timeout
```

诊断结果：终端通过 `http://127.0.0.1:7897` 的代理能够连接 Docker Hub，直接连接会超时；Docker 服务没有代理环境变量。

使用 [Docker 官方的 systemd 代理配置方式](https://docs.docker.com/engine/daemon/proxy/)，在当前主机执行：

```bash
cd /home/mango/ai/Echo-Mate/snowboy
sudo install -D -m 0644 docker-http-proxy.conf /etc/systemd/system/docker.service.d/echo-mate-proxy.conf
sudo systemctl daemon-reload
sudo systemctl restart docker
sudo docker pull ubuntu:16.04
sudo env SNOWBOY_BUILD_PROXY=http://127.0.0.1:7897 bash build_pmdl_env.sh
```

这里分别处理两层网络：Docker 服务代理负责拉取镜像；构建参数负责容器中 apt/pip 下载。构建脚本启用主机网络，让构建步骤能访问主机的 `127.0.0.1:7897`。

这是本次主机的代理地址，换电脑或换代理端口时需要调整。下载期间代理需保持运行。

`DEPRECATED: The legacy builder is deprecated` 是构建器弃用警告，不是本次构建失败的原因。本次无需先安装 buildx 就完成了构建。

用户终端最终确认：

```text
Successfully installed numpy-1.16.6 scipy-1.2.3
Successfully built ecd274b0b9c3
Successfully tagged snowboy-pmdl:latest
```

以上镜像 ID 是本次构建日志记录，后续重建可能不同。

### 12.4 `model/`：个人录音和生成模型

```text
model/
├── record1.wav   # 第一次注册录音
├── record2.wav   # 第二次注册录音
├── record3.wav   # 第三次注册录音
├── my_wake.pmdl  # 三段录音生成的个人模型
└── test.raw      # 后续独立录制的检测音频
```

前三个 WAV 文件是生成工具的输入，`my_wake.pmdl` 是输出。`test.raw` 是检测程序的输入，用来验证模型是否能够识别新的录音。

WAV 带有文件头，记录采样率、声道等信息；RAW 只有音频样本，不自带这些参数。虽然本次两类录音都采用相同的 PCM 编码，但文件不能只靠改扩展名互换。

生成后的 `.pmdl` 是模型文件，无法像文本配置一样直接编辑唤醒词。需要换词时，应在新的录音目录中录制三个新 WAV 文件，再生成另一个模型。

这些是个人实验数据，已被 `.gitignore` 排除。如果需要保留本次结果，应另行备份录音和模型；下载源码或重新编译不能恢复这些个人数据。

`examples/Python/pmdl/lib` 和 `examples/Python/resources` 是符号链接，并非另一份独立库或资源。因此复制生成工具时，不能仅复制 `generate_pmdl.py`，还需要保持库、资源及其相对目录关系。本次 Dockerfile 复制整个 `seasalt-src/` 来保留这些关系。

生成流程在 Python 层的主要调用是：

```text
generate_pmdl.py
    → snowboy_pmdl_config.py 选择 zh/personal_enroll.res
    → SnowboyTemplateCut.CutTemplate() 处理录音片段
    → SnowboyPersonalEnroll.RunEnrollment() 完成注册
    → 保存 my_wake.pmdl
```

Python 脚本负责组织流程，核心计算由预编译的 `_snowboy.so` 执行。仓库提供的生成方式不是一套可随意修改网络结构、从零训练权重的完整 Python 深度学习训练工程。

其他平台的检测库不代表各个平台都支持本次个人模型生成。这里实际使用的是 Ubuntu 16.04/Python 2.7 的 x86_64 生成库，所以采用容器环境。
